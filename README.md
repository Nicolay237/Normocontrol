# Нормоконтроль

Веб-сервис автоматической проверки .docx/.pdf на соответствие ГОСТ 7.32-2017.
Два раздела: **ВКР** (`/vkr`) и **курсовая** (`/coursework`) — у каждого свой профиль норм.

## Запуск для разработки

```bash
pip install -r requirements.txt
python app.py                       # API на http://127.0.0.1:5000

cd frontend && npm install
npm run dev                         # React на http://localhost:5173 (проксирует /api на Flask)
```

## Продакшн (без Docker)

```bash
cd frontend && npm install && npm run build && cd ..
pip install -r requirements.txt
gunicorn app:app --bind 0.0.0.0:8080 --workers 1 --threads 8 --timeout 120
```

Flask раздаёт собранный фронтенд из `frontend/dist`.

## Деплой на VPS (основной)

Российский VPS: сайт открывается у всех провайдеров без VPN, учётные записи хранятся в РФ
(152-ФЗ). Хватает 1 vCPU / 1–2 ГБ RAM / 15 ГБ диска, Ubuntu 22.04 или 24.04.
`docker-compose.yml` поднимает три контейнера: приложение, PostgreSQL (данные в томе `pgdata`)
и Caddy, который сам выпускает и продлевает HTTPS-сертификат.

```bash
# 1. Docker и swap (сборка фронтенда на 1 ГБ RAM без swap может не уместиться)
curl -fsSL https://get.docker.com | sh
fallocate -l 2G /swapfile && chmod 600 /swapfile && mkswap /swapfile && swapon /swapfile
echo '/swapfile none swap sw 0 0' >> /etc/fstab

# 2. Код и настройки
git clone https://github.com/Nicolay237/Normocontrol.git /opt/normocontrol
cd /opt/normocontrol
cp .env.example .env && nano .env

# 3. Запуск и проверка
docker compose up -d --build
curl http://127.0.0.1:8080/health
```

Перенос учёток со старой базы (Neon) — пароли сохраняются, повторный запуск дублей не создаёт:

```bash
docker compose exec -e SOURCE_DATABASE_URL="postgresql://…старая база…" app python scripts/migrate_users.py
```

Домен: у регистратора A-записи `@` и `www` на IP сервера. Как только DNS обновится, Caddy получит
сертификат, `www.` перенаправляется на основной домен.

- обновление до последней версии из GitHub — `./deploy/update.sh`;
- резервная копия базы — `./deploy/backup.sh` (в `backups/`, хранится 14 дней), в cron:
  `0 4 * * * /opt/normocontrol/deploy/backup.sh`;
- логи — `docker compose logs -f app`.

## Деплой на Render

В репозитории есть `render.yaml`: на render.com → **New → Blueprint** → выбрать репозиторий,
Render соберёт сервис по `Dockerfile` (фронтенд собирается внутри образа) и будет
передеплоивать его на каждый push в `master`.

Вручную: **New → Web Service** → репозиторий → Runtime **Docker**, Health Check Path `/health`
и переменные окружения из таблицы ниже.

| Переменная | Зачем |
|---|---|
| `DATABASE_URL` | PostgreSQL для учётных записей (`postgresql://…`). Без неё учётки живут во временном SQLite-файле и **пропадают при каждом деплое** — админка об этом предупреждает. |
| `SECRET_KEY` | Подпись cookie сессий. В Blueprint генерируется автоматически. Смена = все выходят из аккаунтов. |
| `ADMIN_LOGIN`, `ADMIN_PASSWORD` | Первый администратор: создаётся при запуске, если такого логина ещё нет. Пароль потом меняется на сайте; переменная его не перезаписывает. |

База: бесплатный PostgreSQL от [Neon](https://neon.tech) (не удаляется по сроку) или Render
Postgres (бесплатный тариф Render удаляет базу через 30 дней — для постоянной работы нужен
платный). Строку подключения вставить в `DATABASE_URL`.

Сервер работает одним процессом с потоками (`--workers 1 --threads 8`): ограничение числа попыток
входа и кеш проверок живут в памяти процесса. Загруженные и исправленные файлы хранятся час во
временной папке. Тариф free засыпает после 15 минут простоя (первый запрос после этого ~1 минута).

### Домен и поисковики

| Переменная | Зачем |
|---|---|
| `SITE_URL` | Основной адрес, например `https://normocontrol.site`. Задаётся **после** подключения домена: включает 301-перенаправление с `www.` и технических адресов хостинга, попадает в `canonical` и `sitemap.xml`. |
| `YANDEX_VERIFICATION`, `GOOGLE_VERIFICATION` | Коды подтверждения прав из Яндекс Вебмастера и Google Search Console (значение `content` мета-тега). |
| `AUTOFIX_PRICE` | Цена автоисправления для пользователей без входа, ₽ (по умолчанию 99). Показывается в карточке покупки. |
| `PAYMENTS_ENABLED` | `1` — когда подключим оплату; пока кнопка покупки объясняет, что оплата скоро заработает. |

SEO (`seo.py`): у `/`, `/vkr`, `/coursework`, `/gost` свои `<title>`, описание, canonical, Open Graph
(картинка `frontend/public/og.png`), schema.org; текст страницы отдаётся готовым HTML внутри
`#root`, чтобы его видел робот Яндекса без JavaScript. `/robots.txt` закрывает служебные разделы,
`/sitemap.xml` перечисляет публичные страницы. Статья «Требования ГОСТ» — `content/gost.json`
(её читают и сервер, и React).

## Доступ и учётные записи

- **Проверка** оформления доступна всем без входа.
- **Регистрация** (`/register`) открыта всем: email + пароль, вход сразу. Не больше 5 регистраций
  с одного IP в час; закрыть регистрацию — `REGISTRATION_ENABLED=0`.
- **Автоисправление** бесплатно только тем, кому доступ открыл администратор (флаг `free_autofix`,
  кнопка с подарком в `/admin`), и самим администраторам. Остальным — карточка покупки; оплата
  подключается в `can_autofix()` в `auth.py`, `/api/fix` отвечает им `402 payment_required`.
- Учётки университета выдаёт администратор на странице `/admin`: по одной или группой списком ФИО
  (логины придумываются из ФИО, пароли случайные, можно скачать CSV) — бесплатный доступ у них
  сразу. При первом входе пользователь обязан сменить временный пароль. Есть сброс пароля,
  блокировка и удаление.
- **Оплата** (`payments.py`, ЮKassa): `YOOKASSA_SHOP_ID` и `YOOKASSA_SECRET_KEY` в `.env`; без них
  кнопки оплаты объясняют, что оплата скоро заработает. Покупка — только с аккаунтом и подтверждённой
  почтой: заказ (`orders`) → страница ЮKassa → возврат на `/pay/<заказ>`. Статус платежа сайт всегда
  спрашивает у API ЮKassa (по возврату покупателя и по уведомлению `POST /api/payments/webhook`),
  телу уведомления не доверяет; оплаченное начисляется ровно один раз: +1 исправление
  (`users.autofix_credits`) или +30 дней подписки. Чеки самозанятого — вручную в «Мой налог»,
  список оплат с отметкой «Чек выдан» — в `/admin`.
- **Почта** (`mailer.py`): при регистрации приходит код из 6 цифр (страница `/verify`), пока почта
  не подтверждена — автоисправление и оплата недоступны. «Забыли пароль?» (`/forgot`) — сброс по коду.
  Настройки SMTP в `.env`: `SMTP_HOST` (почта рег.ру — `mail.hosting.reg.ru`), `SMTP_PORT` (465),
  `SMTP_USER`, `SMTP_PASSWORD`, `MAIL_FROM`. Пока они пустые, подтверждение отключено.
  Для разработки `SMTP_HOST=console` — письма печатаются в журнал.
- **Документы для оплаты** (`legal.py`): `/offer` (оферта), `/refund` (правила возврата),
  `/privacy` (политика ПД), `/consent` (согласие на обработку ПД), `/contacts` (реквизиты и цены).
  Реквизиты — из `.env`: `LEGAL_NAME`, `LEGAL_INN`, `CONTACT_EMAIL`, `CONTACT_PHONE`; пока их нет,
  в тексте видны пометки «[укажите …]», а в `/admin` — предупреждение. Регистрация требует отметки
  согласия, время согласия хранится в `users.consent_at`.
- **Подписка** — `SUBSCRIPTION_PRICE` ₽ в месяц (по умолчанию 299) и `SUBSCRIPTION_LIMIT`
  автоисправлений за календарный месяц (по умолчанию 30). Пока оплата не подключена, подписку
  выдаёт администратор в `/admin` («Подписка 30 дней» — продлевает от текущей даты окончания).
  Использования — таблица `autofix_log`; бесплатный доступ лимит не тратит.
- **Раздел «ГОСТы»** (`/standards`, `checker/standards.py`): пользователь сам отмечает стандарты.
  Взаимоисключающие группы: оформление текста (ГОСТ 7.32-2017 / ГОСТ Р 2.105-2019 / ГОСТ Р 7.0.11-2011)
  и список источников (ГОСТ Р 7.0.100-2018 / ГОСТ 7.1-2003); ссылки по ГОСТ Р 7.0.5-2008 — с любыми.
  Автоисправление — только для набора из ГОСТ 7.32 + 7.0.100 (+ 7.0.5).
- **Дополнительные проверки вуза** (`checker/packs/`) — только тем, кому их включил администратор
  (кнопка «Проверка …» у пользователя в `/admin`, таблица `user_packs`). Настройки пакета — JSON
  в `/admin` → «Дополнительные проверки» (таблица `check_packs`, хранятся только отличия от значений
  по умолчанию из кода). Сейчас есть пакет `pgups`: титульный лист (Приложение Ж), задание на ВКР
  (Приложение К) и порядок «аннотация → содержание → введение» по СМК РД 02.01.18-2021.
  Новый вуз — новый модуль рядом с `pgups.py` и запись в `PACKS`.
- Титульный лист, задание и всё до первого структурного элемента (АННОТАЦИЯ, РЕФЕРАТ,
  СОДЕРЖАНИЕ, ВВЕДЕНИЕ…) не проверяются и не исправляются по правилам основного текста.
- Новые колонки таблицы `users` добавляются при запуске сами (`_add_missing_columns`): учётки,
  выданные до появления регистрации, сохраняют бесплатный доступ.
- Защита: пароли — хеши (werkzeug scrypt), сессия в подписанной HttpOnly-cookie,
  сброс/блокировка сразу завершают сессии, 10 неудачных попыток входа → пауза 15 минут,
  запросы с чужих сайтов отклоняются (проверка Origin).

## Работа с отметками

Для .docx в отчёте есть кнопка «Работа с отметками» (`GET /api/annotated/<upload_id>`):
копия работы, где абзацы с ошибками подсвечены жёлтым, а на полях — примечания Word с текстом
замечаний (одно примечание на абзац, общие замечания — к первому абзацу или к разделу).
Текст работы не меняется. Модуль — `checker/annotate.py`; место замечания хранится в
`Issue.anchor`. Для PDF остаётся HTML-отчёт.

## Автоисправление

Автоисправление (`checker/fixers.py`, `POST /api/fix`, только .docx) меняет лишь оформление:
поля, шрифт, кегль, цвет, интервал, отступы, выравнивание, заголовки, подписи, нумерацию страниц,
пробелы, лишние пустые абзацы. Исходный файл не меняется, после исправления документ проверяется
заново, и всё, что починить нельзя (пропуски в нумерации, отсутствующие разделы), остаётся в отчёте.

## Тесты

```bash
pip install -r requirements-dev.txt
python -m pytest tests
```

Тесты генерируют .docx/.pdf: эталон не должен давать замечаний, а каждое намеренное
нарушение — замечание в своей категории.

Проверка «от противного» (`tests/mutations.py`, `tests/test_mutations.py`): в эталонную курсовую
(`scripts/make_sample_coursework.py`) по одной вносятся ~80 ошибок по ГОСТ 7.32-2017, ГОСТ Р 7.0.100-2018
и правилам для листингов; каждая должна попасть в отчёт, исправимые — уйти после автоисправления.
Все совместимые ошибки сразу — `python scripts/make_broken_coursework.py "samples/Курсовая с ошибками.docx"`
(рядом пишется список внесённых ошибок). Новая найденная проблема = новая запись в каталоге.

## Нормы

Источник — ГОСТ 7.32-2017, раздел 6. Что ГОСТ требует прямо, а что — типовая практика вузов:

| Параметр | ГОСТ 7.32-2017 | В профиле |
|---|---|---|
| Поля | лев. 30, прав. 15, верх./нижн. 20 мм | правое допускается 10–15 мм |
| Шрифт | Times New Roman (рекомендуется), ≥ 12 пт, чёрный | ВКР — ровно 14 пт; курсовая — 12–14 пт |
| Интервал | полуторный | 1,5 |
| Абзацный отступ | 1,25 см | 1,25 см |
| Нумерация страниц | внизу по центру, без точки | проверяется |
| Заголовки структурных элементов | по центру, ПРОПИСНЫМИ, без точки, с новой страницы | проверяется |
| Заголовки разделов | полужирный, без точки, с новой страницы | проверяется |
| Подписи | «Рисунок N – Название» по центру под рисунком; «Таблица N – Название» слева над таблицей | проверяется |
| Список источников | п. 6.16 + ГОСТ Р 7.0.100-2018: «Фамилия, И. О.», «. – », «Москва : Изд-во», URL и дата обращения; ссылки [N] по порядку | проверяется, однозначные ошибки исправляются |

Правило «в оглавлении жирным только заголовки верхнего уровня» в ГОСТ отсутствует —
это требование вуза, оставлено из прежней версии (`check_toc` в `docx_checks.py`).
