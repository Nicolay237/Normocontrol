# Нормоконтроль

Веб-сервис автоматической проверки .docx/.pdf на соответствие ГОСТ 7.32-2017.
Два раздела: **ВКР** (`/vkr`) и **курсовая** (`/coursework`) — у каждого свой профиль норм.

## Запуск для разработки

```bash
pip install -r requirements.txt
python app.py                       # API на http://127.0.0.1:5000

cd frontend && npm install
npm run dev                         # React на http://localhost:5173 (проксирует /api на Flask)
```

## Продакшн (без Docker)

```bash
cd frontend && npm install && npm run build && cd ..
pip install -r requirements.txt
gunicorn app:app --bind 0.0.0.0:8080 --workers 1 --threads 8 --timeout 120
```

Flask раздаёт собранный фронтенд из `frontend/dist`.

## Деплой на Render

В репозитории есть `render.yaml`: на render.com → **New → Blueprint** → выбрать репозиторий,
Render соберёт сервис по `Dockerfile` (фронтенд собирается внутри образа) и будет
передеплоивать его на каждый push в `master`.

Вручную: **New → Web Service** → репозиторий → Runtime **Docker**, Health Check Path `/health`
и переменные окружения из таблицы ниже.

| Переменная | Зачем |
|---|---|
| `DATABASE_URL` | PostgreSQL для учётных записей (`postgresql://…`). Без неё учётки живут во временном SQLite-файле и **пропадают при каждом деплое** — админка об этом предупреждает. |
| `SECRET_KEY` | Подпись cookie сессий. В Blueprint генерируется автоматически. Смена = все выходят из аккаунтов. |
| `ADMIN_LOGIN`, `ADMIN_PASSWORD` | Первый администратор: создаётся при запуске, если такого логина ещё нет. Пароль потом меняется на сайте; переменная его не перезаписывает. |

База: бесплатный PostgreSQL от [Neon](https://neon.tech) (не удаляется по сроку) или Render
Postgres (бесплатный тариф Render удаляет базу через 30 дней — для постоянной работы нужен
платный). Строку подключения вставить в `DATABASE_URL`.

Сервер работает одним процессом с потоками (`--workers 1 --threads 8`): ограничение числа попыток
входа и кеш проверок живут в памяти процесса. Загруженные и исправленные файлы хранятся час во
временной папке. Тариф free засыпает после 15 минут простоя (первый запрос после этого ~1 минута).

## Доступ и учётные записи

- **Проверка** оформления доступна всем без входа.
- **Автоисправление** — бесплатно для пользователей университета после входа (`/login`).
  Для остальных позже появится оплата: точка расширения — `can_autofix()` в `auth.py`.
- Учётки выдаёт администратор на странице `/admin`: по одной или группой списком ФИО
  (логины придумываются из ФИО, пароли случайные, можно скачать CSV). При первом входе
  пользователь обязан сменить временный пароль. Есть сброс пароля, блокировка и удаление.
- Защита: пароли — хеши (werkzeug scrypt), сессия в подписанной HttpOnly-cookie,
  сброс/блокировка сразу завершают сессии, 10 неудачных попыток входа → пауза 15 минут,
  запросы с чужих сайтов отклоняются (проверка Origin).

## Работа с отметками

Для .docx в отчёте есть кнопка «Работа с отметками» (`GET /api/annotated/<upload_id>`):
копия работы, где абзацы с ошибками подсвечены жёлтым, а на полях — примечания Word с текстом
замечаний (одно примечание на абзац, общие замечания — к первому абзацу или к разделу).
Текст работы не меняется. Модуль — `checker/annotate.py`; место замечания хранится в
`Issue.anchor`. Для PDF остаётся HTML-отчёт.

## Автоисправление

Автоисправление (`checker/fixers.py`, `POST /api/fix`, только .docx) меняет лишь оформление:
поля, шрифт, кегль, цвет, интервал, отступы, выравнивание, заголовки, подписи, нумерацию страниц,
пробелы, лишние пустые абзацы. Исходный файл не меняется, после исправления документ проверяется
заново, и всё, что починить нельзя (пропуски в нумерации, отсутствующие разделы), остаётся в отчёте.

## Тесты

```bash
pip install -r requirements-dev.txt
python -m pytest tests
```

Тесты генерируют .docx/.pdf: эталон не должен давать замечаний, а каждое намеренное
нарушение — замечание в своей категории.

## Структура

```
app.py                  Flask: /api/profiles, /api/check, /api/report/<id>, раздача React
normocontrol.py         CLI
checker/norms.py        профили норм (ВКР, курсовая) — ЗДЕСЬ меняются числа под требования вуза
checker/docx_checks.py  проверки .docx
checker/docx_utils.py   вычисление фактического форматирования (стили → docDefaults)
checker/pdf_checks.py   проверки .pdf (по координатам, оценочно)
checker/fixers.py       автоисправление .docx
checker/annotate.py     копия работы с подсветкой и примечаниями Word
auth.py                 учётные записи: вход, сессии, админка (/api/login, /api/admin/...)
checker/typography.py   пробелы, пустые строки
checker/report.py       модель отчёта, HTML для скачивания
frontend/               React + Vite (react-router)
tests/                  pytest
```

## Нормы

Источник — ГОСТ 7.32-2017, раздел 6. Что ГОСТ требует прямо, а что — типовая практика вузов:

| Параметр | ГОСТ 7.32-2017 | В профиле |
|---|---|---|
| Поля | лев. 30, прав. 15, верх./нижн. 20 мм | правое допускается 10–15 мм |
| Шрифт | Times New Roman (рекомендуется), ≥ 12 пт, чёрный | ВКР — ровно 14 пт; курсовая — 12–14 пт |
| Интервал | полуторный | 1,5 |
| Абзацный отступ | 1,25 см | 1,25 см |
| Нумерация страниц | внизу по центру, без точки | проверяется |
| Заголовки структурных элементов | по центру, ПРОПИСНЫМИ, без точки, с новой страницы | проверяется |
| Заголовки разделов | полужирный, без точки, с новой страницы | проверяется |
| Подписи | «Рисунок N – Название» по центру под рисунком; «Таблица N – Название» слева над таблицей | проверяется |

Правило «в оглавлении жирным только заголовки верхнего уровня» в ГОСТ отсутствует —
это требование вуза, оставлено из прежней версии (`check_toc` в `docx_checks.py`).
